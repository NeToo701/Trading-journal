# Журнал трейдера: окремий застосунок

Особистий журнал угод, який виглядає й працює так само, як журнал на сайті «Розбір ринку», але **не пов'язаний з сайтом і не потребує сервера**.
Це звичайні файли (HTML, CSS, JavaScript): їх можна покласти на GitHub Pages і користуватись постійно.

- Записи, фото й відео зберігаються **у твоєму браузері** (IndexedDB). Працює без інтернету.
- Налаштовувані поля, статистика за днями, тижнями, місяцями, кварталами й роками, розбір місяця, календар днів, сетапи.
- **Імпорт** з Notion (ZIP із Markdown і CSV, зі скріншотами сторінок) і з будь-якої CSV-таблиці (Excel, Google Таблиці, експорт брокера).
- **Експорт** у CSV для Excel і **резервна копія** одним ZIP-файлом (з усіма фото й відео).
- **Реєстрація й синхронізація між пристроями** через Firebase (необов'язково, безкоштовно). Без неї журнал працює повністю локально.
- Встановлюється як застосунок на телефон і комп'ютер (PWA).

---

## 1. Запуск за 5 хвилин: GitHub Pages

1. Створи на github.com новий репозиторій (наприклад `journal`). Для безкоштовного GitHub Pages репозиторій має бути **публічним**. Це нормально: у репозиторії лише код застосунку, твої записи туди не потрапляють.
2. Завантаж у корінь репозиторію **весь вміст цієї папки** (кнопка *Add file → Upload files*). Файл `index.html` має лежати в корені репозиторію.
3. *Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: `main`, папка `/ (root)` → Save*.
4. Через 1-2 хвилини журнал відкриється за адресою `https://ТВІЙ_НІК.github.io/journal/`.
5. На телефоні відкрий цю адресу й обери «Додати на головний екран» (на iPhone: «Поділитися» → «На початковий екран»); на комп'ютері в Chrome/Edge натисни «Встановити як застосунок».

Оновлення застосунку: завантаж нові файли в репозиторій поверх старих. Дані від цього не зникають, вони зберігаються окремо, в браузері.

> Важливо: адреса `…github.io/journal/` для браузера це «окремий сайт». Дані прив'язані до цієї адреси й цього браузера. Якщо ти змінив адресу (перейменував репозиторій), дані старої адреси не з'являться на новій: перенеси їх через резервну копію або хмару.

## 2. Збережи дані: це найважливіше

Без хмари записи лежать лише в браузері цього пристрою. Їх може стерти очищення даних сайтів, перевстановлення браузера, нестача місця на телефоні. Тому:

- Раз на тиждень-місяць натискай **«Дані й хмара» → «Зберегти копію (ZIP)»** і клади файл у надійне місце. Застосунок нагадає, якщо копій давно не було.
- Або підключи хмару (розділ 3): тоді дані ще й лежать у твоєму акаунті.
- У вікні «Дані й хмара» є кнопка «Захистити дані від автоочищення»: вона просить браузер не стирати журнал без твоєї згоди.
- Відновлення з копії **додає** записи до наявних, нічого не видаляє. Якщо запис є і в копії, і на пристрої, лишається той, що змінено пізніше.

## 3. Реєстрація й синхронізація між пристроями (Firebase)

Потрібно один раз, ~10 хвилин, безкоштовно (тариф Spark, без картки).

1. Відкрий <https://console.firebase.google.com>, увійди з Google-акаунтом, **Create a project** (назва будь-яка, Google Analytics можна вимкнути).
2. Зліва **Build → Authentication → Get started → Sign-in method → Email/Password → Enable → Save**.
3. Зліва **Build → Firestore Database → Create database** → режим **Production** → найближчий регіон (наприклад `eur3` або `europe-west`) → Enable.
4. У Firestore відкрий вкладку **Rules**, видали все, що там є, встав вміст файлу **`firestore.rules`** з цієї папки й натисни **Publish**. Ці правила дозволяють кожному користувачеві бачити тільки власні дані й нічого більше. **Без цього кроку синхронізація не працюватиме (або дані будуть незахищені).**
5. Шестерня біля *Project Overview* → **Project settings → General → Your apps → іконка `</>` (Web)** → дай назву, Firebase Hosting **не** вмикай → *Register app*. З'явиться блок `const firebaseConfig = { apiKey: ..., authDomain: ..., projectId: ..., appId: ... }`. Скопіюй його.
6. **Authentication → Settings → Authorized domains → Add domain**: додай `ТВІЙ_НІК.github.io`.
7. Відкрий журнал → **«Дані й хмара»** → встав блок у поле «Налаштування Firebase» → «Зберегти й підключити». Після цього з'явиться форма «Створити акаунт / Увійти».
   Замість цього можна вписати налаштування у файл `firebase-config.js` (інструкція всередині файла) і завантажити його на GitHub: тоді на всіх твоїх пристроях вводити їх не треба.
8. Створи акаунт (пошта й пароль від 6 символів) на першому пристрої. Дані з пристрою автоматично потраплять у хмару. На другому пристрої встав ті самі налаштування (або вони вже є у `firebase-config.js`) і **увійди в той самий акаунт**: журнал підтягнеться.

Як це працює:

- Журнал завжди спершу пишеться на пристрій, а потім у фоні відправляється в хмару (за 3 секунди після зміни, при відкритті, при поверненні інтернету, або кнопкою «Синхронізувати зараз»). Без інтернету все працює, зміни чекають у черзі й не губляться навіть після перезавантаження.
- Якщо один запис змінено на двох пристроях, **лишається зміна, зроблена пізніше** (за годинником пристрою). Видалення працює так само: видалення пізніше за правку прибирає запис, а правка пізніше за видалення повертає його. Тому тримай правильний час на пристроях.
- Забутий пароль: на формі входу «Забув пароль»: лист прийде на пошту.
- Якщо на пристрої вже є дані без акаунта, при першому вході вони **об'єднуються** з тим, що є в акаунті. Якщо на пристрої лежать дані *іншого* акаунта, застосунок спитає, чи видалити їх з пристрою (можна спершу зберегти копію).

Що важливо знати про хмару:

- **Фото** у хмару потрапляють стисненими (до 640 КБ, JPEG): так вміщаються в безкоштовні ліміти Firebase. Оригінал лишається на пристрої, де фото додано. На іншому пристрої буде стиснена версія.
- **Відео** в хмару **не** відправляються (їм потрібен платний тариф Firebase Storage). Відео лишаються на пристрої, де додані, і потрапляють у резервну копію ZIP.
- Безкоштовна квота Firebase: 1 ГБ даних (це приблизно 1000-1500 фото), 20 тис. записів і 50 тис. читань на добу. Для особистого журналу цього з запасом. Якщо добова квота вичерпана, синхронізація відновиться наступного дня, а на пристрої нічого не втрачається.
- Дані в Firestore не шифруються окремо від Google (стандартне шифрування Firebase), їх бачиш ти і ніхто інший завдяки правилам з кроку 4. Власник проєкту Firebase (ти) технічно має доступ до консолі.
- Рекомендовано: **Google Cloud Console → APIs & Services → Credentials → твій Browser key → Application restrictions → HTTP referrers** і вказати `https://ТВІЙ_НІК.github.io/*`. Так ключ не зможуть використовувати з чужих сайтів. Ключ Firebase для веб це не пароль, а публічний ідентифікатор, але обмеження не завадить.

## 4. Імпорт з інших джерел

Кнопка **«Імпорт»** у журналі.

- **Notion**: відкрий базу з угодами → «…» → *Export* → формат *Markdown & CSV* (з підсторінками) → отриманий ZIP завантаж у журнал. Скріншоти зі сторінок угод прикріпляться до відповідних записів.
- **CSV**: з Excel, Google Таблиць, експорту брокера (*Файл → Зберегти як → CSV*). Кодування UTF-8, Windows-1251 і UTF-16 розпізнаються самі, роздільник теж (кома, крапка з комою, табуляція).
- Далі застосунок сам пропонує, яка колонка якому полю відповідає (дата, інструмент, напрямок, ціни, результат, емоції, помилки тощо). Перевір і за потреби зміни зіставлення.
- Обов'язкова лише колонка з датою входу. Рядки без дати пропускаються й показуються у звіті.
- Повторний імпорт того самого файла не дублює записи (збіг за датою входу, інструментом і напрямком). Це можна вимкнути галочкою.
- Власний експорт CSV цього журналу (і журналу на сайті) імпортується назад без ручного зіставлення.
- Нові значення зі списків (таймфрейми, емоції, сетапи) додаються автоматично, якщо їх не надто багато.

## 5. Обмеження й чесні застереження

- **Хмару не перевірено на живому Firebase**: у середовищі, де застосунок створювався, не було доступу до серверів Google. Уся наша логіка синхронізації (черга, злиття, видалення, конфлікти, стиснення фото, сторінки) перевірена автоматичними тестами на імітованій хмарі, а запити до Firebase написані за офіційною документацією SDK 10.14. Якщо при першому вході побачиш помилку, застосунок покаже її текст (наприклад «не ввімкнено вхід за поштою» чи «правила Firestore»), і вона майже напевно виправляється одним із кроків розділу 3. Локальна частина (усе, крім хмари) перевірена повністю.
- Інтерфейс написано без бібліотек і збирачів: нічого встановлювати не треба.
- Ліміти: до 20 журналів, 60 полів у журналі, 5000 записів у журналі, 20 файлів до запису, фото до 10 МБ, відео до 150 МБ, імпорт до 300 МБ. Обсяг файлів обмежений місцем, яке браузер дозволяє сайту (показано в бічній панелі).
- Це особистий записник, а не торгова порада чи сигнал. Застосунок нічого не знає про ринок.
- Safari/iPhone: браузер може стерти дані сайту, який не відкривали близько тижня, якщо застосунок не встановлено на головний екран. Встановлюй і роби копії.

## 6. Структура папки

```
index.html            сторінка застосунку
firebase-config.js    налаштування Firebase (необов'язково, спочатку порожні)
firestore.rules       правила безпеки Firestore: встав у консолі Firebase
manifest.webmanifest  дані для встановлення як застосунку
sw.js                 робота без інтернету
assets/               стилі, шрифти, іконки
js/                   інтерфейс (той самий, що на сайті) і вікно «Дані й хмара»
lib/                  «двигун» у браузері: сховище, обчислення, імпорт, копії, синхронізація
tests/                автоматичні перевірки
README.md, DEV.md     ця інструкція й опис для розробки
```

Для подальших змін (в іншому чаті чи вручну) дивись `DEV.md`.
